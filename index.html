Primero se entiende, después se escribe.

Antes de tipear tu primera consulta conviene saber qué es una base de datos, cómo se organiza y por qué el lenguaje SQL tiene tres "idiomas" distintos: DDL, DML y DCL. Leé este manual una vez con calma y volvé cuando quieras: después te esperan 10 niveles de práctica real.

01

¿Qué es una base de datos?

Una base de datos es un sistema ordenado de guardar información para que después sea fácil encontrarla, actualizarla y cruzarla. No es magia: es información organizada en tablas, como el cuaderno de asistencia del preceptor — una hoja por curso, con nombre, DNI y faltas.

Ahora imaginá ese cuaderno con superpoderes: buscar cualquier alumno en milisegundos, ordenar por nota, contar ausentes de un solo comando. Eso es una base de datos.

El software que la administra se llama SGBD (Sistema Gestor de Bases de Datos): MySQL, PostgreSQL, SQLite, SQL Server. Vos le hablás en SQL (Structured Query Language) y él hace el trabajo pesado.

TABLA: curso_4b — así se ve la información adentro
Una fila (registro): todos los datos de UNA alumna, en este caso Valentina.
Una columna (campo): un mismo tipo de dato para todas las filas.
Una celda: el valor exacto donde fila y columna se cruzan.
02

La clave primaria: cada fila tiene su DNI

Fijate en la columna id de la tabla de ejemplo: es la clave primaria (PRIMARY KEY). Es un número que no se repite y que identifica a cada fila de forma única, aunque dos alumnos se llamen igual.

Gracias a la clave primaria el sistema sabe exactamente qué fila actualizar o borrar, y puede relacionar tablas entre sí (por ejemplo, conectar cada nota con su alumno). En casi todas las tablas que vas a crear, la clave primaria será la columna id.

REGLA DE OROSin clave primaria, dos filas idénticas serían indistinguibles. Con ella, cada registro es único e irrepetible.

DDLDEFINIR

Lenguaje de Definición de Datos

Data Definition Language · construye y destruye la ESTRUCTURA

El DDL define cómo está armada la base: qué tablas existen, qué columnas tienen y de qué tipo son. No trabaja con los datos de adentro, sino con el "mueble" que los contiene.

CREATE crea una tabla nueva · ALTER modifica su estructura · TRUNCATE la vacía entera · DROP la elimina por completo, estructura incluida.

Cada columna además acepta restricciones: NOT NULL, UNIQUE, DEFAULT valor y AUTOINCREMENT en la clave primaria numérica.

ANALOGÍADDL es el carpintero: arma el mueble (o lo manda a leña). Después viene otro idioma para guardar cosas adentro.
CREATE TABLE estudiantes (
  id     INTEGER PRIMARY KEY AUTOINCREMENT,
  nombre TEXT NOT NULL,
  nota   REAL DEFAULT 0
);

DROP TABLE estudiantes;  -- ¡la borra toda!
DMLMANIPULAR

Lenguaje de Manipulación de Datos

Data Manipulation Language · trabaja con los DATOS de adentro

El DML es el que más vas a usar: consulta, agrega, modifica y borra filas, sin tocar la estructura.

SELECT consulta · INSERT agrega filas · UPDATE modifica las existentes · DELETE elimina. SELECT merece capítulo propio: es el comando más usado de todo SQL — leer nunca modifica nada.

ANALOGÍASi DDL armó el mueble, DML es quien guarda, ordena, revisa y saca lo que hay en los cajones.
SELECT nombre, nota FROM estudiantes
WHERE nota >= 6;

INSERT INTO estudiantes (nombre, nota)
VALUES ('Valentina', 8.5);

UPDATE estudiantes SET nota = 9 WHERE id = 1;
DCLCONTROLAR

Lenguaje de Control de Datos

Data Control Language · administra PERMISOS

El DCL responde una pregunta clave: ¿quién puede hacer qué? En una escuela no cualquiera puede borrar notas: el administrador otorga y quita permisos con dos comandos.

GRANT otorga un permiso (leer, insertar, borrar…) sobre una tabla a un usuario. REVOKE se lo quita. Así se protege la información de errores y miradas ajenas.

EN ESTE LABORATORIOEl DCL necesita un servidor real con usuarios, así que acá no se practica — pero sí entra en la teórica y en el parcial: con GRANT el admin decide quién ve cada tabla, y con REVOKE le cierra la puerta.
-- Dar permiso de LECTURA a un usuario:
GRANT SELECT ON estudiantes TO alumno_consulta;

-- Quitarle el permiso de BORRAR:
REVOKE DELETE ON estudiantes FROM alumno_consulta;
03

Cómo funciona el laboratorio

Después del manual empezás en el Nivel 1 y avanzás hasta el 10: cada nivel se desbloquea al completar el anterior. Cada uno tiene una teoría exprés, una misión con objetivos que el sistema valida automáticamente, y un reto extra que da XP de bonificación.

Escribís SQL de verdad en la consola (con ayuda de los botones de inserción rápida), ejecutás con Ctrl + Enter y el resultado siempre se muestra como tabla. Si cambiás datos (INSERT, UPDATE, DELETE, DROP…), el panel "Base de datos en vivo" se actualiza al instante. Cada nivel guarda sus propios resultados y el texto de tu consola mientras navegás por el sistema: al avanzar de nivel, el panel de resultados arranca limpio, sin arrastrar consultas del nivel anterior. Podés restaurar los datos del nivel cuando quieras, y tu progreso queda guardado en este navegador.

CONSEJO DE CÁTEDRALos errores de SQL se leen, no se temen: el sistema te va a decir qué falló y por qué. Un informático que lee errores aprende el doble de rápido. Y si te trabás, cada nivel tiene pista y solución — pero probá primero por tu cuenta.
